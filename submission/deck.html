The harm

The most expensive second in Indian digital finance

A person is about to approve a UPI transfer or wire. Then a message arrives that weaponises trust — and AI has made all three forms cheap to fake.

🎙️ Cloned-voice orders

A WhatsApp voice note in the "boss's" or a relative's voice: "transfer now, I'll explain later." Seconds of audio clone a voice.

🎬 Deepfake video calls

A "relationship manager" or executive on a video call authorising a payout — face and voice synthesised.

🖼️ Forged proof

Fake payment-success screenshots, doctored bank SMS, AI-generated KYC selfies used to unlock a release of funds.

  • Primary user: the person/agent at the payment decision — retail UPI user, SME accountant, or bank ops reviewer.
  • Bounded moment: pre-payment verification. Not "scan the internet" — one message, one decision, one safe answer.

How detection works

Honesty tiering: the model decides, heuristics only nudge

Primary (model-backed)Dual-CNN image · wav2vec2 voice-clone → calibrated P(AI)
＋
Supporting (heuristic)ELA, FFT, noise, phase, rPPG, lip-sync — bounded ±0.15 nudge
→
Calibrated verdictAI / Human / Inconclusive → escalate

The one rule

A supporting signal can adjust confidence but can never flip a confident model verdict. This kills the "10 shaky heuristics outvote the real model" failure.

We don't guess

When the primary model isn't confident, the verdict is Inconclusive and the case routes to human review — no confident-looking wrong answer.

Calibrated, not vibes

Platt scaling maps the model score to a real probability; uncalibrated output is labelled and capped. Confidence means something.

Replaces the old hand-tuned rule cascade. Primary models: dima806 + Ateeqq (image), wav2vec2-xlsr (voice).

5
Strongest evidence & the record

Provenance + a chain-of-custody case file

  • C2PA / Content Credentials verified cryptographically — a signed origin claim beats any pixel heuristic.
  • EXIF (piexif) + JPEG quant — camera-capture chain vs AI-software marker vs messaging recompression.
  • Precedence rule: verified provenance sets the headline; forgeable EXIF only fills an Inconclusive gap.
  • Every check → a case: ID, SHA-256 of the media, verdict, timestamp — media itself never stored.
  • Exportable evidence report to forward to a bank/fraud team.

7
Safety, privacy & responsible AI

Built so being wrong can't cause harm

  • No auto-blocking / accusations on a single weak signal — Truthy advises, the human acts.
  • Human review path for every escalated / low-confidence case, gated by a reviewer key (fails closed).
  • Consent + purpose: uploader confirms authorisation; enforced server-side.
  • Privacy: media processed transiently and never stored — only metadata + a SHA-256 hash.
  • False-positive care: WhatsApp recompression no longer forces "fake"; ambiguity → review.
  • Adversarial awareness: heuristics can't drive the verdict, so poisoning them can't flip it; provenance forgery is capped to a nudge.

Inputs, models, storage & interfaces

Inputs, consent & provenance

  • Voice/video/image up to 20–50 MB; consent flag mandatory (UI + server).
  • Provenance inputs: C2PA manifest, EXIF (Make/Model/DateTime/GPS/lens), JPEG DQT.
  • SHA-256 computed at ingest as the evidentiary anchor.

Models & rules

  • Primary: dima806 + Ateeqq (image), wav2vec2-xlsr (voice) — HF, pinned; CPU/INT8 or HF Inference API.
  • Calibrator: Platt (scipy), persisted calibration.json.
  • Supporting: numpy/scipy DSP + rPPG + lip-sync (bounded influence).

Storage & data boundaries

  • SQLite case ledger (metadata + hash + verdict + review state).
  • No media at rest; temp files unlinked in a finally block.
  • Calibration + model weights are the only persisted model artifacts.

Interfaces & outputs

  • REST: /api/verify, case/report/escalate/review; SSE for live image.
  • Outputs: JSON report envelope + printable HTML evidence report.
  • UI: unified verify page + analyst review queue.

Decision flow, safeguards & validation

Decision & escalation flow

  • Confident primary → calibrated verdict + risk + recommendation.
  • Uncertain / conflicting / no-primary → Inconclusive → auto-queue for human review.
  • Reviewer confirms or overrides with a note; decision stored on the case.

Security & privacy

  • Review endpoints require REVIEWER_KEY (no same-origin bypass), fail closed.
  • Transient media, hash-only retention; consent-gated ingest.
  • Tighten CORS on mutations; rate-limited public endpoints.

Adversarial risk

  • Heuristics can't drive the verdict → poisoning them can't flip it.
  • Provenance forgery capped to a nudge; only verified C2PA overrides.
  • Unknown/ambiguous defaults to escalation, not a confident wrong call.

Performance & validation

  • Image ~2–8s CPU; thread-pool capped; single worker (no model duplication).
  • Validation: LOO accuracy + ECE today; ROC + per-attack sets next.
  • Calibration refresh as labelled data grows; disclosed sample size.
